# Research

A source packet is not automatically a dump. Research before writing.

1. Name the decision and durable result that the sources must support.
2. Check authority. An unresolved dump or source packet without create authority writes nothing. If the owner authorized creation and one durable result remains, research and create in the same turn.
3. Ask only when two supported readings change the durable result or Things form. Never ask the owner to repeat the sole supported result.
4. Make a private coverage list. Include each owner-named source, relevant replies, topic, and local evidence source. Record one material fact, or exclusion reason, and where it goes: done now, Project note, Task, or outside the Project.
5. Preserve the owner's evidence scope. Actual use is not installed inventory. One named harness cannot replace another. A named thread includes relevant replies.
6. Gather current facts from direct, suitable sources. Batch independent reads. Use one fallback for an unavailable source. If the owner offered an authenticated browser for that source, use it before declaring the source unavailable. Name unavailable evidence; do not invent it. The Project owns any broader accepted audit.
7. Reading a source now removes a Read Task. It does not remove a required evidence result that later work must use.
8. Collapse aliases and methods before splitting finishes. Two names for one durable artifact share one finish. A pin, tool, repository, harness, or extraction method is evidence or delivery unless the owner accepts another artifact.
9. For a clearly new create, do not search Things or Areas. Search once only when the owner signals matching work. Use one distinctive title token. One empty result ends the search.
10. Summarize facts, material uncertainty, and choices separately. Split only distinct durable results.
11. Map each owner requirement to done now, a Project Task, a Project note, or outside as optional or continual work. Every accepted Things change must appear in this map.

If the owner must still open a source, that Task is first and its URL is on that Task. Keep owner-named titles when they describe one finish. Example: replace the kitchen tap → Project `Replace kitchen tap` with `Find three suitable taps`, `Measure the sink`, `Order one`.

Chat already has the brief. Leave undecided work outside active Tasks. Optional or continual work is not this Project. Put durable sources and context in Markdown notes on the Task that uses them. Put executable work in Tasks.

Read [form](form.md) before creation. Done when each named source and evidence scope is accounted for, unavailable evidence is named, and every accepted Things change is accounted for.
