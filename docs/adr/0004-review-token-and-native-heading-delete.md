# Review pages are write tokens; heading delete is one native op

A weekly-review dogfood spent more turns on protocol than on judgment.
Heading delete went stale because the planner rewrote every assigned
child, including completed and trashed rows the organize layout hid.
Review pages returned revisions but no context, so inbox walks copied
`if_revision`. Area `id` returned a shell.

`things_read` review pages now mint a context and short refs. An Area
or Project `id` lists children. `delete_headings` and heading
`lifecycle=delete_permanently` emit one `permanent_delete`; native
apply already detaches occupants. We rejected a fourth tool and a
`look` address language because the three-tool seam was not the gap —
the gap was round-trips, hidden occupants, and approve/stale on
heading delete.
